# 球队颜色、控球邻近判断与 UI 优化

## 思路的依据

已直接读取用户指定的 [Roboflow notebook](https://github.com/roboflow/notebooks/blob/main/notebooks/how-to-track-football-players.ipynb) 的代码单元。它的 `get_player_in_possession` 要求只有一个球检测，然后遍历球员，将框四周扩大 30 像素，返回首个包含球中心的球员。示例没有按球衣颜色比例区分两队；其中 PLAYER/REFEREE 等颜色是绘制类别配色。页面也标注该 notebook 已被 Football AI 替代。

本次借鉴的是“球中心与扩大球员框的空间邻近”原则。球队颜色比例来自用户提出的方向，具体上身裁剪、HSV 阈值、背景过滤和时序投票为本项目新增实现。没有安装整套旧 notebook 的 YOLOv5/ByteTrack 环境，复用当前 YOLO/ByteTrack 和 OpenCV，避免替换已跑通的检测模型。

## 球队如何判断

1. YOLO 检测球员框，截取横向 22%–78%、纵向 25%–55% 的上身区域。目视比较发现，原先更靠上的裁剪包含深蓝球衣的白色肩袖，降低了颜色区分度，因此裁剪下移至胸部。
2. 对与其他球员框重叠的像素不采信；剩余可见区域不足 55% 时，本次采样拒绝。移除偏暖色的地板/皮肤候选，避免整框地板比例主导分类。
3. 将裁剪转换为 HSV。默认队1为低饱和高亮白色，队2为深蓝或低亮度深色。每队比例为匹配且未被过滤的像素数，除以可见裁剪像素数。最大比例至少 0.22、与次名差至少 0.14 才形成有效证据。
4. 约每 0.10 秒采样一次，每个轨迹保存最近 9 次观察，按颜色差值加权。首次需要至少 3 次支持、80% 加权占比；反转已有队伍需要至少 5 次支持与相同占比。长期无色彩证据或切镜头清空为 UNKNOWN。
5. 每帧输出 `teams` 和 `team_evidence`，包含两队占比、采样帧和拒绝原因。占比及差值是规则证据，不是校准后的概率。

默认白/深蓝只表示球衣类别，不自动识别 NBA 队名。配置中的 `label` 可映射为已知队名（UI 建议英文）。更换为红色、橙色或相似色球衣时，还需校准当前暖色过滤规则，不能保证只换配置即可泛化。

## 谁控制球

沿用“控制球，包含运球”的定义。对球员框按自身尺寸扩展横向邻域、头顶和脚下运球区域，筛选包含球中心的所有候选。对候选进行归一化距离、包含率及置信度评分，使用最佳候选与次名的差距，避免 notebook 中遍历顺序决定控球者。

实际检测置信度至少 0.25 才能支持新控制者或转移；较弱实际检测只可支持已有控制者。预测/插值仍不能产生新控球。连续确认、换人确认、缺球有限保持和分离释放继续生效；修复旧持球者提前释放后意外缩短换人确认时间的问题。

这仍然是空间与时间启发式，不是手部接触或动作模型。高置信度假球、多人争球和空中传球仍可能误判，球队颜色也不能替代球的位置证据。

## 视频帧对齐修复

在这段原视频上直接比较顺序解码与随机跳帧：OpenCV 请求第 100 帧、报告下一位置 101，实际图像与顺序解码第 150 帧完全相同。随机取帧会使球员框和球衣裁剪错位。

`VideoFrames` 已改为从已知帧位顺序 grab/read；向后取帧重新打开解码。球队采样使用连续帧。此修复优先保证正确对齐；向后随机访问会增加解码开销。

## UI

- 球员脚下小环、头顶深底白字标签：WHITE / NAVY / UNKNOWN + 轨迹 ID；白队用浅色，深蓝队用明亮蓝色，未知灰色。
- 控球者绿色框和 CONTROL；缺球短时保持为橙色 HOLD。标签避让、边缘裁切和高对比背景减少遮挡与看不清的问题。
- 球用位置圆环；黄色明确区分预测/插值。顶部小状态卡显示当前控制轨迹、球队、状态和球来源。
- 默认简洁视图；`--details` 显示原速度、战术图、关键点和统计，`--debug` 显示候选球。编号是轨迹 ID，不是球衣号码或球员姓名。

## 验证与边界

保留第一阶段代码快照于 `../analysis/stage2_baseline`，原阶段视频仍在 `output_videos/stage1_flagg.mp4`。

测试命令：`python -m unittest discover -s tests -v`。新增覆盖整框地板/短裤干扰、相似颜色、重叠拒绝、多帧确认、错误单帧、切镜头、未知队伍统计、弱球不确认控球、候选顺序独立、转移确认计时和随机跳帧偏差、边缘 UI。完整运行与抽查数据保存在第二阶段视频旁的 summary、debug 和 validation 文件。

最终 31 项测试全部通过。完整视频处理耗时约 225.18 秒；新视频逐帧解码确认 1291 帧、59.94 FPS。修复后的索引取帧与顺序解码第 100 帧完全一致。视频仍不包含原音轨。

本轮对六个预先选定帧的球员裁剪进行了工程目视抽查，51 个队伍可辨认的框作为参考；混合两人的 F1000/ID41、F1200/ID51 不计入。参考由本次分析生成，未经独立人工复核，不能当作全视频正式准确率：

| 51 个抽查框 | 第一阶段 CLIP | 本轮颜色比例 |
|---|---:|---:|
| 与目视参考一致 | 42 | 47 |
| 错队 | 9 | 1 |
| 待确认 | 0 | 3 |

仅本次抽查显示错队减少；颜色算法、时序规则和取帧修复同时变化，不能把收益单独归因于颜色比例。剩余错队为 F700/ID27，待确认为 F300/ID21、F500/ID27、F500/ID21。参考标签及逐例差异保存在 `output_videos/stage2_validation.json`，裁剪拼图为 `jersey_crops_*.jpg`。

全视频 11636 个球员框中，白队 5439、深蓝队 4767、未知 1430。控球标签从第一阶段 761 帧降至 628 帧，未知状态增加；这是提高新控球证据门槛后的保守结果，不代表已测得控球准确率改善。球轨迹和检测权重保持不变，球位置误判仍存在。

已目视检查原视频第 100、300、500、700、1000、1200 帧的球员裁剪。现有跟踪 ID 在遮挡后仍可能交换给不同球队的球员，颜色投票需要重新确认，期间可能暂时显示旧队伍；例如第 700 帧附近的轨迹 27。颜色相似、重叠以及侧身导致未知也属于当前边界。球的误检仍未通过新权重训练解决，不能把更多标签或更少切换解释为更高准确率。
