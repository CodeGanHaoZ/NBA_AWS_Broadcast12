# 第一阶段实现与验证

## 范围

持球采用“控制球，包含运球”的定义。本阶段保留原检测权重，优化跟踪关联、短时缺球处理与控球状态判断，未训练新模型、未增加球员姓名识别或跨镜头身份重识别。

输入：`C:\Users\12908\Desktop\黑客松\NBA\train_video\训练_弗拉格2月1日.mp4`。
原版代码快照：`../analysis/stage1_baseline`。原版模型推理改为分批流式读取以限制内存，检测阈值及跟踪、球过滤、插值、持球算法保持原版；对比视频统一按输入帧率生成，避免播放速度干扰。

## 实现

- 球员：先筛选 Player 类，再做 ByteTrack；检测阈值 0.10、轨迹激活阈值 0.35；短暂丢失保留关联机会，显示框独立平滑。
- 球：综合候选置信度、预测距离与尺寸变化关联；按画面尺寸和时间设置移动门限。实际检测、预测、插值、丢失分别记录，最多预测约 0.10 秒、插值约 0.067 秒短缺口，不做开头回填或无限补球。
- 控球：按球员框尺度和包含运球的区域评分，增加候选差距、连续确认、转移确认、有限缺球保持和分离释放。预测/插值不能确认新控制者；缺球打断待确认计数。
- 镜头与事件：启发式切镜头检测并重置关联/控球状态；长时间未知后不直接延续传球/抢断事件。
- 工程：使用输入 FPS，修复绘制跳过首帧，流式读写减少内存；缓存按视频/权重/代码/依赖/参数摘要隔离，输出逐帧诊断与汇总。

## 回归验证

`python -m unittest discover -s tests -v`：19 项全部通过。覆盖缺球计数、运球区域、误候选、确认转移、限时释放、镜头重置、24/30/60 FPS 时间换算、预测与插值限制、事件间隔及视频首帧/帧率/帧数。

输入共 1291 帧，1920×1080，59.940014 FPS，时长约 21.538 秒。改进版完整处理并按同帧率输出；运行结果与耗时以 `output_videos/stage1_flagg.summary.json` 为准。

最终完整运行耗时约 244.87 秒。改进视频与左右对比视频均已逐帧解码验证：1291 帧、59.94 FPS，记录在 `output_videos/decode_validation.json`。视频写出沿用 OpenCV 流程，不保留原视频音轨。

## 目视发现与边界

左右对比视频：`output_videos/comparison/before_after.mp4`；逐帧指标：`comparison_summary.json`；抽样截图保存在同目录。

已检查第 100、300、500、700、1000、1200 帧：第 100 帧两版均标出右侧运球者；第 300 帧新版本的预测位置偏离真实球，第 500 帧附近仍存在右侧背景假球候选，第 1000 帧也存在球的位置误判。检测模型误检或持续漏检仍会影响关联与控球。后续应针对这些困难片段补充球的标注和模型微调，再考虑局部高分辨率检测或手部姿态证据。

轨迹仍有碎片，球队分类、场地投影和速度估计沿用现有方法，需要独立验证。切镜头检测是启发式规则；本视频未触发切镜头，真实切镜头泛化效果尚未验证。第一阶段只完成机制改进与回归验证，未解决所有实战误差。
