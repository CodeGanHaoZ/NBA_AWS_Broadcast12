# 看板、点位与控球调试

## 本轮默认行为

左上角战术球场看板、原视频的球场关键点和编号恢复为默认显示。右上角状态卡避开战术看板。`--details` 额外打开速度、距离和累计统计，不再是看板/点位的必要开关。

持球一旦确认，就保留原持球者，不因缺球、球远离或旧轨迹暂时不可见而超时清空。另一位球员必须与真实检测到的球连续关联 16 帧（严格大于 15 帧）才转移；缺球、插值、预测、候选换人或不可靠证据会中断计数。第一次确认持球者仍使用原连续确认时间。切镜头清空状态，避免延续到另一个镜头。

原持球者暂时不可见时只保留其逻辑 ID，画面不制造球员框。该规则也会在球已离手但无人连续确认时保持原控制者，属于按用户定义的持球推定，并非逐帧接触检测。

## 两个可以直接修改的配置文件

- `debug_config.json`：颜色比例、投票、裁剪、控球参数。
- `team_profiles.example.json`：每队 HSV 颜色范围和显示名称。

修改保存后重新运行，配置在程序启动时加载。例：

```powershell
cd C:\Users\12908\Desktop\黑客松\NBA\NBA_ans
python main.py "..\train_video\训练_弗拉格2月1日.mp4" --output_video output_videos/debug_test.mp4 --config debug_config.json --team_profiles team_profiles.example.json --debug
```

YOLO/球轨迹与球队配置缓存已分开。只改队伍颜色、比例、投票或控球参数时可复用检测缓存，仍会重新计算球队/控球并渲染视频。不要添加 `--no_cache`，除非确实需要重跑检测。改变检测参数、权重或源代码会重新建立相应缓存。

## 颜色比例与确认参数

比例的取值为 0–1，例如 0.22 表示 22%。

| 参数 | 默认值 | 用途与调节方向 |
|---|---:|---|
| `team_min_ratio` | 0.22 | 胜出队伍颜色至少占可见裁剪区域 22%；提高更谨慎，降低可减少 UNKNOWN |
| `team_ratio_margin` | 0.14 | 两队颜色占比至少相差 14 个百分点；提高减少混色误判，降低更容易确认 |
| `team_min_visible_ratio` | 0.55 | 与其他球员框重叠后，上身区域至少剩 55% 可见；提高更保守 |
| `team_sample_seconds` | 0.10 | 上身采样间隔；降低响应更快，但投票样本之间更相似 |
| `team_vote_window` | 9 | 最近采样次数窗口，整数 |
| `team_acquire_samples` | 3 | 首次确认需要支持采样数，整数，不能超过窗口 |
| `team_switch_samples` | 5 | 更改已有队伍需要支持采样数，整数，不能超过窗口 |
| `team_vote_share` | 0.80 | 该队在有效颜色证据中需达到的加权占比；提高更稳定、响应更慢 |
| `team_filter_warm` | true | 过滤暖色地板/皮肤候选；红橙球衣调试时可关闭，但需防止地板干扰 |

建议每轮只改一个参数。例如 UNKNOWN 太多，先将 `team_min_ratio` 改到 0.18；两队比例接近时，再尝试将 `team_ratio_margin` 改到 0.10。错队增加就回调。不能把 UNKNOWN 减少直接当作准确率提高。

## 上身裁剪参数

均相对球员框：左/右为宽度比例，上/下为高度比例。

| 参数 | 默认值 |
|---|---:|
| `team_crop_left` | 0.22 |
| `team_crop_right` | 0.78 |
| `team_crop_top` | 0.25 |
| `team_crop_bottom` | 0.55 |

例如纵向 0.25–0.55 就是从球员框顶部向下 25%–55% 的胸部区域。左右、上下必须严格递增。白色肩袖误导深蓝队判断时，可适当下移裁剪；过低会混入短裤和背景。

## 每队 HSV 范围

编辑 `team_profiles.example.json`，每个范围为 `[[H下限,S下限,V下限],[H上限,S上限,V上限]]`。OpenCV H 范围 0–179，S/V 范围 0–255；同队多个范围取并集。

- 白队默认 `[0,0,145]` 至 `[179,65,255]`。`145` 是最低亮度，`65` 是最高饱和度。阴影中的白衣漏识别可适当降低最低亮度；提高饱和度上限会纳入更多非白色区域。
- 深蓝队默认 `[90,45,25]` 至 `[140,255,190]`，另包含亮度 15–85 的深色像素。深色头发/背景误判时可收窄或删除第二个范围。
- `label` 为画面标签，建议使用英文/数字。队1/队2的 UI 色环用于区分队伍，不直接表示 HSV 色值。

## 控球参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `possession_hold_until_transfer` | true | 缺球持续保留原持球者，仅由确认转移或切镜头改变 |
| `possession_switch_frames` | 16 | 连续新候选帧数，不随 FPS 换算，16 表示大于15帧 |
| `possession_evidence_confidence` | 0.25 | 新确认/转移所需球检测置信度门槛 |

设 `possession_hold_until_transfer=false` 可恢复旧的限时保持模式；此时使用 `possession_switch_seconds`、`possession_grace_seconds`、`possession_release_seconds`，帧阈值不生效。

## 如何看诊断结果

视频旁的 `.debug.jsonl` 每行对应一帧。`team_evidence` 给出颜色占比 `ratios`、采样帧 `sample_frame`、拒绝原因 `reason` 与最终队伍 `assigned_team`。采样间隔内会沿用最近采样证据，因此采样帧可能早于当前帧。

`possession.pending_holder` 是正在确认的新候选，`pending_frames` 为连续计数，`transfer_required_frames` 默认 16。`holder_visible` 表示保留的控制轨迹是否仍在画面，`state=held` 表示推定保持。
