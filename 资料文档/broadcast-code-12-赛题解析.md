## 二、赛题核心分析

### 2.1 一句话概括

> **数据进去，能播出去的比赛画面出来。**

做一个 AI Agent：输入深度赛场历史/单场数据 → 输出叠加了数据可视化的真实比赛视频（必须），最好还有解说（可选）。

### 2.2 赛题方向的理解

**不是把表格搬上屏幕，而是让数据回到它诞生的那块地板上**——回到那次挡拆、那次收缩、那次不该出手却出手了的瞬间。

关键认知转变：

| 错误理解（会被扣分）        | 正确理解（得分方向）                 |
| ----------------- | -------------------------- |
| 做一个数据看板/Dashboard | 做视频内嵌的 overlay（叠加层）        |
| 把指标列在画面角落当装饰      | 指标要锚定在球场空间位置上（谁、在哪、什么时间）   |
| 数据堆砌              | 数据要解释战术：这次挡拆为什么成功、这个空档怎么来的 |
| 赛后报告式呈现           | 转播级呈现：名字浮在球员头顶、箭头画跑位、色块框空档 |

### 2.3 交付要求拆解（必须项 vs 可选项）

**必须项（Must Have）**：

1. 接收官方提供的深度赛场数据（历史数据或单场数据）
2. 将数据可视化**叠加进一段真实的比赛视频**
3. 在处理后的视频中能直观看到：
   - 球员名字浮现在他该在的位置上（球员识别 + 位置跟随）
   - 投篮率、球员引力等深度指标随回合推进出现在画面中
   - 指标能说明正在发生的**战术选择**，成为解读形势与阵型的数据支撑

**可选项（Nice to Have，拉开差距的地方）**：  
4\. 生成解说（AI 生成或人工均可）  
5\. 可视化配合解说：箭头标跑位、色块框空档、画出防守收缩的真实形态（Telestrator 战术板风格）

### 2.4 数据条件（关键约束）

| 项    | 说明                                                |
| ---- | ------------------------------------------------- |
| 官方提供 | 深度赛场数据 + 两段进攻视频（休斯顿火箭、达拉斯独行侠各一段）                  |
| 练习视频 | 当天早上签到抽签发放，用于训练 Agent                             |
| 考试视频 | 当天 18:00 统一发布，不提前提供——**Agent 必须具备泛化能力，不能过拟合练习视频** |
| 自备数据 | 可从 NBA 官网深度数据页抓取更多数据；可自行收集腾讯视频等平台比赛视频用于训练         |
| 合规红线 | 交付物不得含未授权录像，数据来源需披露                               |

### 2.5 赛题边界（明确不做的）

- 不是「数据看板」比赛
- 不做：实时信号接入、数字孪生、跑动轨迹复原、判罚认定、博彩类预测
- **深度数据只有出手瞬间点位，没有逐帧轨迹**——这意味着：

> **最重要的技术推论**：官方数据只给你「出手瞬间」的空间点位快照，而视频是连续的。Agent 必须自己解决「连续视频帧」与「离散数据点」之间的对齐问题——包括时间对齐（数据点对应视频第几秒）和空间对齐（数据坐标对应视频画面像素位置）。这是本赛题最核心的工程难点。

### 2.6 评分导向推断（从推文与赛题描述交叉验证）

1. **看得懂** > 算得准：观众（评委）能一眼看懂球场上正在发生什么
2. **叙事性**：数据要讲出战术故事（"这次收缩是怎么被惩罚的"）
3. **转播质感**： overlay 要融入画面，不像贴上去的 PPT
4. **泛化能力**：练习视频 ≠ 考试视频，硬编码坐标必死
5. **完成度**：12 小时极限赛，先跑通端到端管线，再打磨亮点

## 三、核心技术名词对照词典（队员速查）

> 按「数据底座 → 四大指标 → 算法与工程」三层组织。每条含：定义 / 技术原理 / 案例。

### 3.1 数据底座层

| 术语      | 英文                      | 快速理解                                   |
| ------- | ----------------------- | -------------------------------------- |
| 深度赛场    | NBA Inside the Game     | NBA 与亚马逊云科技联合打造的高阶数据体系，本赛题的数据来源        |
| 光学球员追踪  | Optical Player Tracking | 全场摄像头 + 计算机视觉，不用可穿戴设备就能捕捉全场位置          |
| 3D 姿态识别 | 3D Pose Estimation      | 从视频画面推算人体骨骼关键点的三维坐标                    |
| 骨骼关键点   | Skeleton Keypoints      | 每名球员 29 个身体关节点（头/肩/肘/腕/髋/膝/踝等），60Hz 采样 |
| 60Hz 采样 | 60Hz Sampling           | 每秒 60 帧采集，毫秒级时间分辨率（出手前 1 秒 = 60 帧时序数据） |
| 特征工程    | Feature Engineering     | 把原始坐标流加工成模型可用的几何/运动学特征                 |

**解析**：这套系统对标的是 NBA 官方 Second Spectrum / Hawk-Eye 级别的追踪能力。对参赛队伍的意义：**官方数据源于这套体系，但只下放"出手瞬间点位"**，你要用有限的点位数据反推出可讲的战术故事。

### 3.2 四大核心指标层

#### 指标 1：投篮难度 & 预期命中率（Shot Difficulty & xFG%）

| 项     | 内容                                                                                                                                                                                |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定义    | xFG% = 完全排除球员个体能力，在特定空间与防守干扰下，**联盟平均水准球员**投进该球的概率；投篮难度 = 1 − xFG%                                                                                                                 |
| 技术原理  | 调取出手前 1 秒（60 帧）至球离手的完整时序数据，训练两个概率分类模型：**进攻端 10 项几何/运动学特征**（投篮距离、Z 轴倾角、头部对篮筐可视角度、出手速度、移动速度向量、转体速度、腾空时间等）+ **防守端 10 项干扰特征**（最近防守手到球距离、干扰高度差、手与出手点夹角、视线遮挡指数、身体对抗距离、防守者速度向量、整体防守压力值等） |
| 案例    | 总决赛 G1：文班亚马 26 分 12 篮板但 21 投仅 6 中。尼克斯用唐斯顶防 + 阿奴诺比协防 + 米切尔·罗宾逊补位的"三人车轮阵"，每次出手眼前都有两只长臂——xFG% 判定他整晚都在做"送命题"，不是手感差，是出手环境被压到物理极限                                                       |
| 可视化建议 | 出手瞬间在球员头顶弹出 xFG% 数值条（如 `xFG 31%`），命中低难度球/投进高难度球用颜色区分；"顶着 0.8 防守压力的强投"是最好的解说素材                                                                                                     |

#### 指标 2：防守对位 & 防守压力分数（Defensive Matchups & DPS）

| 项     | 内容                                                                                                                                                                                                      |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定义    | DPS 量化防守球员**每一瞬间**对进攻球员施加的限制程度，取值 0（无人防守）到 1（完全封死）；并据此构建动态"防守数据盒子"，判定每次进攻回合的真正"主防者"                                                                                                                     |
| 技术原理  | 5 攻 5 防每秒生成 25 组对位关系，基于 **7 个加权分项**做空间几何解算：① 绝对距离（欧式距离）② 相对距离（按进攻方距篮距离动态加权）③ 传球路线截断（切入传球连线的垂直距离）④ 篮筐连线位置（失位在身后则惩罚性扣分）⑤ 掩护阻挡惩罚 ⑥ 速度绝对差值 ⑦ 移动方向矢量差（同向同速 = 最高压制分）。加权 + 时序平滑后，用**二分图最优匹配算法**自动裁定对位归属与轮转漏人责任 |
| 案例    | 总决赛 G3 末节：文班一个回合先封弧顶持球人、横移切断底角传球线、回撤篮下钉板大帽沙梅特——传统数据只记 1 次盖帽，DPS 记录了他对 3 名球员全程 0.8+ 的窒息压迫                                                                                                                |
| 可视化建议 | 用色温圈/光圈大小编码 DPS 值画在防守人脚下；对位关系用细线连接攻防两人；"防守压力破表瞬间"（DPS>0.8）给高亮脉冲                                                                                                                                         |

#### 指标 3：球员引力（Gravity）

| 项     | 内容                                                                                                                                              |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 定义    | NBA 首个量化球员**持球及无球状态下扭曲对手防守阵型能力**的指标——防守方因他的存在被迫重心偏移、过度协防、提前轮转的程度                                                                                |
| 技术原理  | 深度学习模型输入球的位置 + 5 名进攻球员空间分布，先推断标准防守战术下各防守人的**理论空间位置**，再将实际防守压力与理论值**逐帧对比取差值** = 引力差值。标定为 −100 到 +100（0 = 联盟平均）；>80 = 未触球已引发恐慌性阵型压缩；>90 = 极强空间扭曲力 |
| 案例    | 总决赛 G3 最后 1 分 53 秒：文班弧顶虚晃掩护，尼克斯两名防守人下意识退到禁区围剿，外线卡斯尔被彻底放空 2 米命中三分。传统数据 3 分全记卡斯尔，引力值证明文班一分没得却做了 80% 的破坏工作（全场 35 次高位掩护）                            |
| 可视化建议 | **这是最适合做出彩效果的指标**：给高引力球员画"引力场"（类似磁场线的形变区/径向渐变圈），当防守人被吸离位置时用箭头回放"他被谁吸走了"；空位出现时圈出空档并标注"引力制造"                                                      |

#### 指标 4：胜率影响力（Leverage Score，2026 全新指标）

| 项     | 内容                                                                                                                                                                                                    |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定义    | 量化**单次事件/单名球员对全场胜负走向的实质性贡献**——不止绝杀，第二节一波 10-0、第三节连续两记三分同样有定局意义                                                                                                                                        |
| 技术原理  | 基于高频胜率预测模型 + **反事实波动算法**：不只算回合前后胜率差，而是比对"已发生结果"与"反向对立结果"的概率摆幅（例：当前胜率 60%，命中三分→75%；若投失且对手收篮板→55%，则摆幅 = 20%）。**全员功劳分配**：结合 xFG% 与 DPS，高难度命中者多得正分、挡拆/助攻创造者分权重、前序抢断者分得转换进攻贡献。基准：1.0 Leverage ≈ 10% 赢球概率波动 |
| 案例    | 总决赛 G4：尼克斯半场落后 29 分（赢球概率一度 1%），终场前 1.2 秒阿奴诺比压哨补篮，一球拉出近 50% 胜率摆幅——进则 3-1 冠军点，不进则 2-2 平                                                                                                                 |
| 可视化建议 | 画面边缘跑一条"胜率心电图"（Win Probability 曲线），关键回合处打点标注 Leverage 值；高 Leverage 回合触发慢镜回放 + 曲线脉冲                                                                                                                    |

### 3.3 算法与工程层（实现 Agent 必备）

| 术语          | 英文                                       | 快速查阅                                                                       |
| ----------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| 二分图最优匹配     | Bipartite Matching / Hungarian Algorithm | 把 5 攻 5 防配成 5 对使总防守压力最大的经典算法，匈牙利法 O(n³) 可解；用于自动判定"谁防谁"                     |
| 反事实分析       | Counterfactual Analysis                  | "如果这球没进会怎样"的概率对比，Leverage Score 的核心思想                                      |
| 时序平滑        | Temporal Smoothing                       | 对逐帧压力值做滑动平均/卡尔曼滤波，防止数值跳动闪烁（overlay 数值稳定的关键）                                |
| 概率分类器       | Probabilistic Classifier                 | 输出 0-1 概率而非硬分类的模型（如逻辑回归/梯度提升/神经网络 + sigmoid）                               |
| 视频叠加层       | Video Overlay                            | 在视频帧上绘制图形/文字的技术层（OpenCV `cv2.putText/line/circle`，或浏览器 Canvas/CSS overlay） |
| 单应性变换       | Homography                               | 把球场俯视图坐标映射到摄像机画面像素的 3×3 矩阵变换——**把"出手点位数据"画到视频正确位置的数学核心**                   |
| 球场标定        | Court Calibration                        | 在视频画面中识别边线/三分线/篮筐等已知尺寸参照物，求解 Homography 矩阵的过程                              |
| 目标检测与跟踪     | Object Detection & Tracking              | YOLO 检测球员 + DeepSORT/ByteTrack 跨帧跟踪，给每个球员维持身份 ID（才能把名字浮在正确的人头上）            |
| 球衣号码识别      | Jersey Number OCR                        | 识别号码辅助球员身份绑定；号码看不清时可用轨迹连续性 + 出场阵容先验推断                                      |
| Telestrator | 战术画板/电视标注                                | 转播中解说员画箭头、画圈的那套工具风格——赛题"箭头标跑位、色块框空档"就是它                                    |
| 解说生成        | AI Commentary / TTS                      | LLM 按回合数据生成解说文案（如 Claude/Amazon Bedrock 上的模型）+ 语音合成（TTS）配音轨                |
| 赔率/胜率模型     | Win Probability Model                    | 输入比分差、时间、球权等状态输出实时胜率的模型，Leverage 的底座                                       |

## 四、Agent 落地管线建议（12 小时工程拆解）

```
01 INPUT      深度赛场数据(JSON/CSV) + 比赛视频
      ↓
02 ALIGN      时间对齐(回合时间戳↔视频时间轴) + 空间对齐(Homography 球场标定)
      ↓
03 DETECT     球员检测+跟踪+身份绑定(名字→画面中的人)
      ↓
04 ANALYZE    按回合计算/挂载四大指标(xFG%·DPS·Gravity·Leverage)
      ↓
05 VISUALIZE  Overlay 渲染(头顶名牌/压力光圈/引力场/胜率曲线/战术箭头)
      ↓
06 NARRATE    回合摘要→LLM 解说文案→(可选)TTS 音轨
      ↓
07 OUTPUT     合成可播出的比赛视频
```

| 阶段   | 建议工具                                 | 风险点                              |
| ---- | ------------------------------------ | -------------------------------- |
| 对齐   | OpenCV 特征点/线检测 + Homography          | 镜头移动/切换机位需分段标定；练习视频与考试视频机位可能不同   |
| 检测跟踪 | YOLOv8/YOLO11 + ByteTrack            | 扎堆遮挡导致 ID 交换；准备阵容先验兜底            |
| 指标   | 官方数据直接给点位，指标按词典公式近似实现                | 时间有限，优先 xFG% 与 Gravity 两个"最出效果"的 |
| 渲染   | OpenCV / FFmpeg 合成；或 Web Canvas 实时叠加 | 数值闪烁——必须时序平滑                     |
