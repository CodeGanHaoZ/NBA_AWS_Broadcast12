# PRD：Broadcast Code — NBA 深度赛场可视化 AI Agent

> 项目：Broadcast Code 12h 黑客松参赛作品（NBA × 亚马逊云科技）
> 版本：v1.0（冻结版） | 作者：产品经理 许清楚 | 状态：评审基线，架构/设计以本 PRD 为唯一需求来源
> 技术形态：Vue 3 + Vite 前端 + Node.js 后端，SVG 战术板重演为主路，真实视频 Canvas overlay 为备路，解说为规则引擎+模板（离线可跑）

---

## 1. 问题陈述

**谁**：篮球内容创作者、深度球迷、赛事数据分析师，以及"看热闹但想看懂门道"的普通观众。

**场景**：回看一场 NBA 比赛的关键回合时，用户只能依赖两种东西——（a）解说员的主观描述，或（b）NBA 官方发布的零散高阶数据截图（如 CourtOptix 的社交媒体贴文）。前者不可验证，后者不可回放。

**痛点**：
1. **高阶数据与比赛画面是割裂的**。CourtOptix 提供"预期投篮价值""引力"等深度指标，但只是静态排行榜和社交贴图，用户无法把它套回到某个具体回合的动态过程中。
2. **"为什么这个回合关键"是黑盒**。普通观众看不出一次底线交叉跑位如何撕开防线；只有职业球队（通过 Second Spectrum、Stats Perform 等企业级付费系统）才能把跑位/引力/防守变化做成动态复盘。
3. **现有工具要么企业级封闭，要么纯手工**。战术板软件（FastDraw）画图强但零自动分析；视频标注工具（Coach's Eye）逐帧手画线，一场比赛标注耗时数小时。

**为什么现在不行**：企业级追踪分析系统（Second Spectrum、OptaAI Studio）不面向个人开放；面向球迷的产品只给结论不给过程；面向教练的工具需要人工画图，没有"读数据 → 自动识别 → 自动呈现 → 自动解说"的完整管线。这就是我们要在 12 小时内跑通的东西。

---

## 2. 产品定位

**一句话定位**：一个离线可跑的 NBA 深度赛场复盘 AI Agent——输入比赛深度数据，自动识别关键回合，用箭头、色块、球员标注在 SVG 战术板上重演跑位与防守变化，并生成与画面逐秒同步的篮球解说，跑通 input → analyze → visualize → narrate 完整管线。

**定位边界**（重要）：
- 这是**黑客松 MVP**，评审场景是 12 小时现场路演（珠海→澳门），首要验收方是评审，而非真实规模用户。
- 产品价值主张是"**管线完整 + 数据可信 + 视觉冲击**"，不是数据规模或模型精度。
- 视觉风格遵循 broadcast-code-ui 终端风范式（深色底 + 数据荧光色系），**禁用紫色到粉色渐变**，禁用 emoji 图标（统一 SVG 图标库，由架构师按项目选型锁定）。

## 3. 目标用户

### 主要用户：黑客松评审（首要验收方）
- **画像**：技术评委（架构师/工程师背景）+ 业务评委（产品/数据背景），单次评审接触产品 5-8 分钟，看四个维度：技术完成度、数据运用、可视化效果、解说表现力。
- **核心诉求**：3 分钟内看懂产品做了什么；能感知"这是完整管线而非 PPT"；能现场操作（点击播放、切换回合）且不翻车。
- **隐含需求**：Demo 必须离线可跑（现场网络不可控）、加载快（路演不能等）、失败有兜底。

### 次要用户 1：篮球深度观众 / 球迷
- **画像**：18-35 岁，日常看 NBA 直播和回放，用过腾讯体育数据面板或 NBA App，对"引力""空位出手"等概念有模糊认知但没见过动态过程。
- **核心诉求**：看懂"这个球为什么空出来了"——用可视化把抽象高阶数据翻译成看得见的跑位。

### 次要用户 2：篮球内容创作者 / 自媒体解说
- **画像**：B 站/抖音/公众号篮球区 UP 主，每周产出战术解析内容，现用 FastDraw 手画战术图 + 剪映标注视频。
- **核心诉求**：低成本产出"数据驱动的战术复盘素材"，一段数据进去、一段带解说的可视化重演出来。

### 4.3 市场空白（我们的差异化依据）

1. **无人提供"数据进 → 复盘出"的自服务管线**。企业级系统（Second Spectrum/Opta）封闭，球迷产品（CourtOptix）静态，教练工具（FastDraw）纯手工。三者之间存在明显的中间地带空白：给创作者和深度球迷的自动化复盘工具。
2. **可视化与解说从未在一个产品里同步**。Stats Perform 的 NLG 证明"数据解说"是成熟方向，但它只服务 B 端转播商；没有任何产品让"画面上的箭头/色块"与"解说词"逐秒对齐地呈现给普通用户。
3. **离线可跑是独特约束优势**。12 小时现场路演 + 澳门跨境场景，竞品全部依赖云与专有数据，我们用规则引擎+模板实现"断网也能完整演示"，这本身就是技术叙事的一部分。

### 4.4 我们的差异化

> 用户为什么选我们：**一个回合，三样东西同时给**——看得见的跑位重演（SVG 箭头/色块/标注）、算得出的深度指标（投篮难度/球员引力/回合关键度）、听得懂的同步解说（与画面逐秒对齐的中文解说流）。且整条管线离线可跑、端到端不超过一次点击。

## 6. 用户故事

**US-01（评审）**：作为黑客松评审，我想打开产品首页点击一次"开始重演"，就能在 3 分钟内看到关键回合被自动识别并以箭头/色块重演 + 同步解说，以便我快速判断技术完成度与产品完成度。
**US-02（评审）**：作为技术评委，我想切换不同比赛数据集并观察回合列表排序变化，以便验证分析引擎是真实计算而非硬编码。
**US-03（深度观众）**：作为想看懂战术的球迷，我想在某个回合暂停画面，看清每名球员的跑位箭头和防守压力色块，再继续播放听解说，以便理解"这个空位是怎么跑出来的"。
**US-04（创作者）**：作为篮球自媒体作者，我想按关键度浏览全部回合并快速跳转，以便挑选值得做进视频的素材。
**US-05（评审/所有用户）**：作为现场演示环境下的用户，我想在断网状态下完整走完主流程，以便确认 Demo 不依赖任何外部服务。

## 7. 明确不做清单（12h 内 Out of Scope）

- 不做用户注册/登录/账户体系
- 不做实时数据接入（直播流、官方 API 对接）——只消费预置离线数据集
- 不做篮球视频画面获取/下载/版权相关功能（F7 overlay 仅在自有样例视频上验证）
- 不做 LLM 大模型调用（解说为规则引擎+模板，离线可跑；LLM 为赛后 Backlog）
- 不做 3D 渲染/AR（Hawk-Eye/GeniusIQ 方向，非 MVP）
- 不做多运动项目扩展（足球/网球等）
- 不做移动端深度适配（桌面 Chrome 优先，投影仪 16:9 路演为第一场景）
- 不做博彩/胜率预测相关功能（合规红线，且偏离叙事）
- 不做用户生成内容分享/导出（视频导出、截图模板）

## 8. 验收标准（Given/When/Then）

**AC-01 数据解析与回合识别**
- Given 本地存在合法的比赛深度数据文件，When 用户加载数据集，Then 系统在 3 秒内完成解析，生成回合列表且每个回合含关键度分值（数值可比较、可排序）。
- Given 数据中某回合存在引力异常（如某球员引力值高于阈值），When 引擎识别该回合，Then 该回合关键度分值高于无异常回合，且解说文本中提及该球员引诱防守的行为。

**AC-02 SVG 战术板重演**
- Given 用户选中任一关键回合，When 点击播放，Then 战术板以不低于 10fps 的动画呈现球员移动，持球者有可辨识的专属标识，跑位箭头随时间逐步绘制，防守压力色块随球员间距变化实时更新。
- Given 回合进行中，When 用户点击暂停，Then 画面立即定格（无可感知延迟），所有标注/箭头/色块保持当前状态完整可见。

**AC-03 深度数据面板联动**
- Given 回合播放中，When 画面帧推进，Then 投篮难度/球员引力/回合关键度三项指标随之更新，且与当前帧时间戳对齐（误差不超过一帧）。

**AC-04 同步解说生成**
- Given 回合播放中，When 解说引擎触发事件（掩护发生/防守换防/空位形成/出手），Then 对应解说字幕在 1 帧内出现在字幕区，解说内容与画面动作语义一致（如画面显示换防时，解说不得描述为包夹）。
- Given 解说模板全部未命中（边缘回合），When 引擎无匹配规则，Then 输出中性的兜底解说文案（如回合时间/比分/持球人描述），绝不出现空白或报错。

**AC-05 播放控制**
- Given 用户处于任一回放状态，When 按空格键，Then 播放/暂停状态切换。
- Given 用户拖动进度条到回合一半位置，When 释放，Then 画面、指标、解说流三者的时间状态一致（解说字幕对应该时间点）。

**AC-06 管线完整性（评审可感知）**
- Given 评审打开产品，When 在首页查看管线状态指示区（input→analyze→visualize→narrate 四阶段状态灯），Then 四阶段全部为完成状态，且各阶段可点击查看对应产出（数据摘要/回合列表/战术板/解说文本流）。

**AC-07 离线可用**
- Given 断网状态，When 用户执行 AC-01 至 AC-05 全部操作，Then 主流程 100% 可用，无任何对外部网络的请求失败。

## 9. 边界条件

- **空状态**：数据集加载前，战术板区显示引导态（示例回合缩略 + "加载数据集"按钮），不显示空白画布。
- **错误状态**：数据文件损坏/字段缺失时，显示明确错误分类（格式错误/字段缺失/版本不支持）+ 重试按钮 + 降级提示（回退到内置兜底数据集），不白屏。
- **加载状态**：数据解析与回合计算期间显示进度指示（骨架屏），预计时间不超过 3 秒（数据集规模受控）。
- **边界值**：回合仅 1 帧（异常数据）时跳过该回合并在列表标记"数据不足"；球员坐标超出场地边界时钳制到界内并在日志标注。
- **并发/性能**：单用户单回合回放，无并发要求；动画帧率下限 10fps（30fps 为目标），回合帧数上限按数据集规范约束。
- **离线**：全部资源本地化（字体/图标/数据），构建产物可单机静态运行。
- **权限/环境**：浏览器媒体自动播放策略——解说如含 TTS 音频则默认静默+用户手动开启（P1 可选），主路以字幕流为准规避自动播放限制。

### 10.1 数据埋点方案（MVP 本地事件日志版）

黑客松场景无真实用户规模，埋点以**本地事件日志**形式实现（localStorage + 控制台输出），路演时可视化为漏斗，同时为赛后迭代预留上报接口：

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | page_view, dataset_loaded | 打开产品 / 数据集加载成功（含耗时属性） |
| 激活 | first_play_started | 用户第一次点击播放（核心激活动作） |
| 留存 | possession_switched, playback_paused/resumed, speed_changed | 回合跳转/播放控制使用频次（演示交互深度） |
| 转化 | narration_displayed, panel_metric_viewed | 解说触发数、指标面板查看数（管线各环节被感知的证据） |
| 异常 | error_occurred | 解析失败/渲染异常/兜底文案触发（降级是否频繁直接影响路演风险） |

- 命名规范：`{对象}_{动作}`（dataset_loaded, possession_switched）
- 属性规范：每事件附带 timestamp、dataset_id、possession_id
- 不采集任何隐私数据，纯本地存储

## 12. 风险与依赖提示（给架构师/设计师的移交说明）

1. **数据集是最大单点风险**：深度数据（投篮难度/引力/关键度）无公开 API，需架构师确认数据来源方案（自构造模拟数据集需在路演中如实标注为"演示数据"，指标计算逻辑真实即可）。
2. **解说语义一致性**是评审可感知的质量点：规则引擎的事件判定与 SVG 重演必须消费同一份事件序列，避免"画面换防、解说包夹"。
3. **视觉风格**由设计师按 broadcast-code-ui 范式执行（深色终端风），本 PRD 只锁定禁项（紫粉渐变/emoji 图标/占位文案）与 AI 标识规范，不做像素级约束。
4. **备路（F7 视频 overlay）永不阻塞主线**：仅当 H11.5 主线全部 AC 通过且有余力时启用。
