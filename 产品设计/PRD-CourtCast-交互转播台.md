## 1. 背景与机会

赛题要求交付一个 AI Agent：接收深度赛场数据 + 真实比赛视频，输出**叠加数据可视化的可播出画面**，可选 AI 解说。评分重心为**交互 · 数据 · UI/UX**。

关键约束（来自赛题解析）：
- 深度数据只有**出手瞬间点位**，无逐帧轨迹 → 时间/空间对齐是最核心工程难点；
- 考试视频当天 18:00 发布 → 必须泛化；
- 明确不做：数据看板、实时信号接入、数字孪生、跑动轨迹复原、判罚认定、博彩预测。

机会点：18 个 GitHub 项目比对证明——检测跟踪、球场标定、指标模型、解说生成全部有成熟开源参照，12h 内的差异化胜负手在**交互体验与数据叙事**，不在重复造 CV 轮子。

## 2. 产品定位

> **一句话：把深度赛场四大指标"翻译"成球场视觉语言的交互式转播台——评委不只是看一段视频，而是亲手玩一块会讲故事的球场。**

三个"看得见"：
1. **看得见人**：名字浮在该在的位置上，行为动作（突破/分球/出手）被识别、被标注、可分享；
2. **看得见数**：引力、命中率、xFG%、投篮热点随回合推进出现在正确的位置与正确的时间戳上；
3. **看得见战术**：多块战术板把跑位、空档、收缩、投篮时机画成动画，因果链讲清"这一球是怎么被创造出来的"。

### 3.2 明确不做（合规红线，写进 PRD 防范围蔓延）

| 不做 | 原因 |
|------|------|
| 数据看板/Dashboard 作为主形态 | 赛题明文"不是数据看板比赛" |
| 实时信号接入、数字孪生 | 赛题边界 |
| **基于数据"复原"跑动轨迹** | 赛题边界。⚠️ 合规说明：本产品战术板上的跑位动画，其位置序列**全部来自对视频本身的 CV 检测**（画面中真实可见），并在 UI 上标注"轨迹源自视频检测"——这是对真实画面的可视化，不是对缺失数据的伪造复原 |
| 判罚认定、博彩预测 | 赛题边界 |
| 未授权录像、不披露数据来源 | 合规红线 |
| 用户系统/账号/收藏等通用 App 功能 | 12h ROI 不足，且偏离赛题 |

## 6. 功能需求详述

### F1 视频播放与帧同步引擎（P0）——时间戳是核心

| 项 | 需求 |
|----|------|
| 描述 | HTML5 `<video>` 播放真实比赛视频；`currentTime` 为全系统**唯一主时钟**，overlay 层、时间轴、战术板、数据面板全部按时间戳对齐到帧 |
| 帧寻址 | 离线管线按 30fps 导出帧级 JSON；前端 `requestVideoFrameCallback`（降级 `timeupdate`+插值）逐帧查最近数据帧 |
| 同步容差 | overlay 与画面偏差 ≤ 2 帧（67ms）；拖拽进度条后 100ms 内全部图层重定位 |
| 验收 | AC-1.1 任意暂停，名牌中心与对应球员躯干中心像素偏差 < 40px（1080p 画面）；AC-1.2 拖动时间轴到任意事件打点，视频、战术板、数据面板同时跳转且一致 |

### F2 Overlay 图层系统（P0）

| 图层 | 内容 | 交互 |
|------|------|------|
| 名牌层 | 球员姓名跟随（ mono 小字 + 细线锚点），遮挡时自动避让 | 开关；悬停高亮并联动数据面板 |
| 指标层 | 出手瞬间弹 xFG% 数值条；防守人脚下 DPS 光圈；引力值以径向场可视化 | 开关；xFG 条命中/未中两态配色 |
| 战术层 | 箭头标跑位、色块框空档、收缩形态描边（Telestrator 风） | 仅在"战术回放"模式出现 |
| 胜率层 | 底部胜率心电图，回合打点 | 打点可点击 → 跳回合 |
| 规则 | 全部图层独立开关、独立可交付；数值必须时序平滑（One Euro 滤波）；出现 0.3s 淡入、回合结束退场，不常驻糊屏 | |

**验收**：AC-2.1 四个图层可两两任意组合开关无错乱；AC-2.2 连续播放 30s overlay 数值无肉眼可见闪烁。

### F3 现实时间轴（P0）——参考 Reality5"现实时间轴"

| 项 | 需求 |
|----|------|
| 结构 | 主进度条 + 回合分段着色 + 事件时间戳打点（如 `07:48.1 突破`、`07:41.3 分球`） |
| 交互 | 点击打点跳转；悬停出事件摘要 tooltip；当前播放位置脉冲 |
| 移动端 | 横向滑动，打点触控区 ≥44×44px |
| 验收 | AC-3.1 每个事件打点时间与实际事件发生帧误差 ≤0.5s；AC-3.2 点击任意打点，F1/F2/F6/F7 同步跳转 |

### F4 球员行为动作识别与分享（P1）

| 项 | 需求 |
|----|------|
| 动作类目 | 突破（Drive）/ 分球（Pass）/ 出手（Shot）/ 掩护（Screen）/ 空切（Cut）——离线管线由轨迹+事件规则判定，写入事件 JSON |
| 呈现 | 事件发生时视频角落弹出动作徽章（如 `01 DRIVE 突破启动 4.8 m/s`，参考 Reality5），同时落入时间轴与因果链 |
| 分享 | 每个事件卡可生成分享图（1080×1350，含动作、时间戳、结构化数据、产品水印），移动端可保存/转发 |
| 验收 | AC-4.1 练习视频主要进攻回合的动作识别人工抽查准确率 ≥80%；AC-4.2 分享图生成 <2s 且信息完整 |

### F5 AI 解说（P1）

| 项 | 需求 |
|----|------|
| 触发策略 | **只在高价值时刻开口**：高 Leverage 回合 / 高难度命中（xFG<35% 且命中）/ 引力制造的空位；其余时间保持安静 |
| 形态 | 下三分之一转播字幕条 + 可开关 TTS 音轨 |
| 生成 | 回合结构化 JSON → LLM（Prompt 注入指标数值与 12 秒念完约束）→ 字幕；TTS 合成音轨 |
| 解释按钮 | 每个回合提供"解释这个回合"按钮（参考 Reality5）：点击后因果链面板展开 + 生成该回合战术解读文案 |
| 验收 | AC-5.1 解说文案必含至少 1 个具体数值（xFG%/引力/距离）；AC-5.2 文案时长 ≤12s 口播；AC-5.3 无虚构——所有数值必须来自 JSON 证据 |

### F6 数据面板（P0）——核心指标必须展示

| 模块 | 内容 | 形式 |
|------|------|------|
| 球员卡 | 选中球员的：命中率（FG%/3P%）、xFG% 均值、**引力值（-100~+100 大数字）**、DPS、Leverage 累计 | 大数字 + mono 标签，Anton 字体 |
| 投篮热点图 | 半场投篮点位分布：点阵密度 + 命中/未中配色 + 各区域命中率 | SVG 半场图 + 点阵（范式签名元素） |
| 球队对比条 | 两队命中率、平均 xFG%、引力榜 TOP3 | 横向条形 |
| 实时跟随 | 随播放进度，"本回合"数据卡自动切换 | 回合切换动效（8px 上移淡入） |
| 验收 | AC-6.1 引力、命中率、进球数、xFG% 四项核心数据在默认视口一屏可见；AC-6.2 热点图每个点位可悬停显示该次出手详情（时间戳+xFG%+结果） |

### F7 战术板模块（P1）——多块 2D 动效战术板

| 战术板 | 内容 | 动效 |
|--------|------|------|
| T1 实时跟随板 | 2D 俯视图同步映射当前画面球员位置（源：视频 CV 检测） | 与视频同步播放，球员圆点平滑移动 |
| T2 跑位复盘板 | 选中回合完整跑位回放：轨迹线 + 箭头 + 速度感 | 播放/逐帧步进/倍速；关键决策点打点（"此处选择分球"） |
| T3 投篮时机板 | 出手前 3 秒逐帧拆解：防守距离变化曲线 + 出手瞬间空间快照 | 时间 scrubber 拖动，"最佳出手窗口"高亮段 |
| T4 空间引力板 | 引力场形变动画：防守人被吸离位置的偏移矢量 | 矢量箭头生长动画；空档出现时色块脉冲 |
| 合规标注 | 每块板角落固定标注 `轨迹源自视频检测` | — |
| 验收 | AC-7.1 T1 与视频画面位置映射误差 < 半个身位；AC-7.2 T2 可完整回放任一回合且箭头方向与真实跑动一致；AC-7.3 移动端可全屏横屏查看 |

### F8 因果链证据面板（P1）——参考 Reality5"是什么创造了最后一个事件"

| 项 | 需求 |
|----|------|
| 结构 | 回合拆解为事件链：`01 突破（4.8m/s 启动）→ 02 分球（5.8m）→ 03 空位出手（xFG 52%）`，每节点标注成立/存疑状态 |
| 证据 | 每事件挂结构化证据列表：突破速度、篮下距离变化、传球距离、防守人偏移量、xFG%——**每句话都能回到证据** |
| 原则 | "现实优先，证据其次，因果第三，语言最后"——所有叙事必须有 JSON 证据支撑 |
| 验收 | AC-8.1 每个解说/解读文案中的数值都能在证据面板找到同值来源 |

### F9 移动端适配（P1）

| 项 | 需求 |
|----|------|
| 断点 | ≥1024 PC 三栏 / 768-1023 两栏 / <768 移动纵向流 |
| 触控 | 全部可点元素 ≥44px；时间轴与战术板支持滑动手势；数据面板底部抽屉两档拖拽 |
| 性能 | 移动端 overlay 渲染降采样（canvas 按 devicePixelRatio 上限 2），保证 30fps |
| 验收 | AC-9.1 iOS Safari + Android Chrome 核心流程（播放/跳事件/看热点/开关图层）全部可用 |

### F10 视觉与动效规范（P0）——broadcast-code-ui 范式

| 项 | 规则 |
|----|------|
| 配色 | 近黑底 `#0B0B0C` + 粉笔白 `#F5F2EC` + 唯一强调信号橙 `#F9530C`（面积 ≤10%）；骨骼/数据标注专用三色除外 |
| 字体 | Anton（大数字/英文标题）+ Noto Sans SC（中文正文）+ JetBrains Mono（数据标签）+ Ma Shan Zheng（标语） |
| 签名元素 | 至少 4 个：球场线背景 / 点阵数据块（热点图）/ Telestrator 标注 / 虚线选框 / 日期 pill / 编号管线 |
| 动效 | 0.2-0.3s，仅 opacity/transform；入场 8px 上移淡入；尊重 prefers-reduced-motion；禁止弹跳缓动 |
| 禁令 | 零 emoji 图标（全 SVG）；禁紫粉渐变；禁硬编码颜色（走 Token）；禁空洞占位文案 |

## 7. 数据需求（tracks.json 消费侧摘要）

| 数据块 | 内容 | 来源 |
|--------|------|------|
| video meta | 时长/fps/对阵双方/球员名单与号码 | 官方数据+视频 |
| calibration | 每视频 Homography 参数（可分段） | 离线标定 |
| frames | 逐帧：球员框+身份 ID+队伍+球场坐标；球位置 | CV 检测 |
| possessions | 回合列表：起止时间戳、事件序列 | 规则引擎 |
| events | 事件：类型/时间戳/参与人/结构化证据（速度/距离/xFG/引力） | 指标引擎 |
| metrics | 球员级聚合：命中率/热点/xFG 均值/引力/DPS/Leverage | 指标引擎 |
| commentary | 回合解说文案 + 触发时刻 | LLM 预生成 |

## 8. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | PC overlay 渲染 ≥30fps；首屏 <3s（JSON 分包：meta 先载，frames 流式） |
| 兼容 | Chrome/Edge/Safari 近两个大版本；iOS Safari、Android Chrome |
| 泛化 | 换视频只需替换 tracks.json + Homography config，前端零改动 |
| 合规 | 页脚固定数据来源披露；无未授权录像；战术板轨迹标注来源 |

## 9. 路演演示脚本（3 分钟，验收走查路径）

1. **0:00-0:30** 打开转播台 → 播放，名牌跟随 + "这不是看板，数据长在球场上"
2. **0:30-1:00** 悬停球员出数据卡（引力大数字）→ 切图层逐个开：xFG → 引力场
3. **1:00-1:40** 点击时间轴"突破"打点 → 跳回合 → 跑位复盘板回放 → 因果链展开"这球怎么被创造出来的"
4. **1:40-2:10** 出手瞬间 xFG 弹出 + 命中 → 投篮热点图展示 → "解释这个回合"AI 解说开口
5. **2:10-2:40** 手机扫码打开移动端 → 滑时间轴、全屏战术板
6. **2:40-3:00** 展示 18:00 考试视频换装机制（换 JSON 即出片）+ 合规声明页收尾

## 11. 风险登记
